# 决策原则

## 合法走法约束（最高优先级）

1. **只能从服务端提供的合法走法列表中选择一步**，不得创造坐标、棋子或走法。
2. 若服务端给出的合法走法列表为空，说明当前无合法走法（对局应已判负），此时不要凭空造步。

## 信息使用限制

3. **不能推断自己不可见的暗子真实身份**。暗子只提供归属标记（红?/黑?）与棋位类型，真实颜色与真实棋种未知，禁止猜测或「脑补」。
4. 所有判断只能基于：已翻开棋子的真实身份、暗子的归属与棋位类型、以及服务端给出的合法走法列表。

## 安全优先

5. **必须优先处理将帅安全和直接威胁**：当前行棋方若被将军，必须选择能解将的走法；存在对方直接威胁（如可吃将、可吃大子）时优先化解。

## 收益与风险权衡

6. **需要比较候选走法的收益与风险**：不仅看眼前是否吃子，还要评估走法之后的局面变化。
7. **不能只追求吃子**：要综合考虑吃子后的反吃风险、子力交换比、走子后的位置与后续影响。

## 返回格式

8. **必须按现有接口要求返回 JSON**，保持原有返回格式，坐标为 0 起始的（行,列）：

```json
{"from":{"r":整数,"c":整数},"to":{"r":整数,"c":整数},"reason":"简短理由"}
```

9. `from` 为起点、`to` 为落点，均为整数坐标；`reason` 为简短中文理由。只返回该 JSON 对象，不要输出多余内容。

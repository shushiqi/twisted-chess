# 棋子价值与交换策略

适用场景：存在吃子机会，需要评估子力交换时。

## 项目内部估值参考

项目规则引擎的估值表（`AI_PIECE_VALUE`）为：

| 棋子 | 估值 |
|---|---|
| 帅/将 | 100000（吃将即胜，最高优先） |
| 车 | 90 |
| 马 | 45 |
| 炮 | 45 |
| 相/象 | 20 |
| 士 | 20 |
| 兵/卒 | 12 |

> 该估值是项目引擎内部的评估口径，用于衡量子力交换的轻重，不代表绝对胜负。

## 要点

1. **帅/将价值最高**：任何能直接吃将的走法都是最高优先级。
2. **大子优先保护**：车、马、炮为大子，尽量避免用大子换小子。
3. **评估交换比**：吃子时比较「我方吃子价值」与「我方被吃风险价值」，选择净收益为正的交换。
4. **暗子价值不确定**：暗子的真实身份未知，吃暗子或翻暗子时按保守估计，不假设其为大子或小子。
5. **不只为吃子而吃**：若吃子后会被反吃且交换为亏，应选择更稳妥的走法。

## 禁忌

- 不要用大子（车/马/炮）去换对方小子（兵/卒/士/象）而不评估反制。
- 不要因暗子「可能是大子」就盲目去吃或盲目去翻。
